# 話術透視鏡 Ad Rhetoric X-Ray — 開發文件

## 一、專案目標

打造一個線上小工具，讓使用者貼上或上傳一段廣告文案，AI 即時標註文案中使用的心理操控話術類型，並給出可信度分數與中性改寫版本，協助消費者（特別是中高齡族群及其家人）快速判斷廣告的可信度，而不需要專業行銷知識。

**前期聚焦領域**：保健食品與藥品類廣告（如誇大療效、醫師背書、限時特價等常見於此類產品的話術），優先針對此類文案做分析與測試，其他品類（如美妝、投資理財）暫不列入前期範圍。

本階段目標：完成可實際上線的小範圍測試版本（非僅 Demo），供 5-10 位使用者實測，並建立資料庫留存分析紀錄供後續讀取查詢。

## 二、使用者情境

- **情境一**：長輩在 LINE 家庭群組收到一則保健食品或藥品廣告，轉傳詢問家人「這個可以買嗎」。子女將文案貼進工具，快速取得好懂的分析結果，作為溝通判斷依據。
- **情境二**：使用者在社群平台看到一篇保健食品／藥品業配文或誇大療效廣告，自行貼上文案或上傳截圖，工具標註可疑話術並給出可信度分數。

## 三、功能清單

### 必做（MVP）

1. **文字輸入**：使用者可直接貼上廣告文案文字。
2. **截圖上傳＋OCR**：使用者可上傳廣告截圖，系統自動辨識圖片中的文字。
3. **AI 話術分析（真實 LLM API 即時分析）**：
   - 依「話術分類系統」標註文案中的可疑片段（恐懼訴求、假稀缺、社會認同操控、權威借位、情緒勒索、誇大療效）
   - 針對每個標註片段，用一句話白話說明「這句話在對你做什麼」
4. **可信度分數與視覺化儀表**：給出整體可信度分數，以直覺儀表呈現（非單純百分比數字）。
5. **中性改寫版**：提供去除話術後的客觀版本文案，供對照原文。
6. **標註呈現**：可疑片段以顏色標籤直接疊加在原文上（非另外產出一份報告）。
7. **資料庫留存與讀取**：每次分析結果（原文、標註、可信度分數、中性改寫版）寫入資料庫，並提供可讀取查詢的介面／端點。
8. **前端＋簡單後端架構**：後端作為串接 LLM API 的中介層，並負責資料庫讀寫。

### 可不做（本階段排除，先不開發）

- 使用者帳號系統／登入
- 瀏覽器外掛
- 多語言支援
- 保健食品／藥品以外品類（美妝、投資理財等）的分析支援
- 累積使用者樣本形成防詐騙知識庫（教育層延伸功能）

> 註：以上「可不做」項目若未來需要，需另行確認後才納入開發範圍。

## 四、頁面流程

```
[首頁／輸入頁]
   │
   ├─ 使用者貼上文字文案  ──┐
   │                        │
   └─ 使用者上傳截圖 → OCR 辨識文字 ──┘
                            │
                    [送出分析請求]
                            │
                  後端中介層 → 呼叫 LLM API
                            │
                    [分析結果頁]
                     ├─ 原文＋顏色標籤標註（疊加顯示）
                     ├─ 每個標註片段的白話說明
                     ├─ 可信度儀表板
                     └─ 中性改寫版對照
                            │
                    分析結果寫入資料庫
                            │
                    [使用者可重新輸入 → 回到首頁]

[查詢頁（讀取資料庫）]
   │
   └─ 讀取已儲存的分析紀錄清單／單筆詳情
```

## 五、資料欄位

不建立使用者帳號系統，但每次分析結果會寫入資料庫，供後續讀取查詢。

**請求（前端 → 後端）**

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| input_type | string | `text` 或 `image` |
| text_content | string | 使用者貼上的文字（input_type=text 時） |
| image_file | file | 使用者上傳的截圖（input_type=image 時） |

**OCR 中介結果**

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| ocr_text | string | 圖片辨識出的文字，回傳給前端供使用者確認／修正後再送分析 |

**分析回應（後端 → 前端）**

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| original_text | string | 原始文案 |
| annotations | array | 標註片段清單 |
| annotations[].text_span | string | 被標註的原文片段 |
| annotations[].category | string | 話術類型（恐懼訴求／假稀缺／社會認同操控／權威借位／情緒勒索／誇大療效） |
| annotations[].explanation | string | 白話說明「這句話在對你做什麼」 |
| credibility_score | number | 整體可信度分數 |
| neutral_rewrite | string | 中性改寫版文案 |

**資料庫（分析紀錄表）**

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| record_id | string/int | 紀錄唯一識別碼 |
| created_at | datetime | 建立時間 |
| input_type | string | `text` 或 `image` |
| original_text | string | 原始文案（含 OCR 辨識後文字） |
| annotations | json | 標註片段清單（結構同分析回應） |
| credibility_score | number | 整體可信度分數 |
| neutral_rewrite | string | 中性改寫版文案 |

## 六、技術限制

- **架構**：前端 + 簡單後端中介層（後端負責串接 LLM API，避免金鑰暴露）。
- **AI 分析**：直接串接真實 LLM API 做即時分析，不使用預設規則/關鍵字比對的假分析。
- **OCR**：截圖上傳需含 OCR 文字辨識功能。
- **無帳號系統**：不需登入機制，但需資料庫存放分析紀錄（不綁定使用者身分，僅存分析內容本身）。
- **內容範圍**：前期分析與話術分類需以保健食品與藥品類廣告為主要適用範圍。
- **上線規模**：供小範圍使用者測試，非大流量正式產品，效能與擴充性以「可穩定跑通測試」為門檻，非企業級高併發。

## 七、驗收標準

1. 使用者可成功以「貼上文字」或「上傳截圖」兩種方式輸入廣告文案。
2. 上傳截圖後，系統能正確辨識出圖片中的文字並顯示供確認。
3. 送出分析後，系統呼叫真實 LLM API 並在合理時間內（測試階段可先以「有回應且不逾時錯誤」為準，不設嚴格秒數）回傳結果。
4. 分析結果需包含：原文標註（顏色標籤疊加）、每段白話說明、可信度分數與視覺化儀表、中性改寫版，四項缺一不可。
5. 標註分類需對應到「話術分類系統」六大類型（恐懼訴求、假稀缺、社會認同操控、權威借位、情緒勒索、誇大療效），不可出現分類系統外的自創類別。
6. 全程不需登入，但每次分析結果需成功寫入資料庫，且可透過查詢頁／端點讀取出先前的分析紀錄。
7. 前期測試文案以保健食品／藥品類廣告為主，系統對此類文案的話術標註結果需合理對應到六大分類。
8. 5-10 位測試使用者可在無額外教學情況下，獨立完成一次「輸入文案 → 取得分析結果」的完整流程。
