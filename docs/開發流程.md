# 話術透視鏡（Script-Insight-Tool / rhetoric-xray）— 開發流程

## 每一輪開場先確認
- GitHub repo：https://github.com/opchannelyeayo-dotcom/ai
- 使用者作業系統：Windows（終端機用 **Git Bash**，不要用 CMD / PowerShell）
- 專案在使用者電腦上的路徑：`C:\Users\user\Desktop\話術透視鏡\Script-Insight-Tool`
  - ⚠️ 這個資料夾是 **Replit 自動同步到本機的**，檔案內容會跟 Replit 保持一致，
    但它自己的 `.git` 歷史是舊的、獨立的、跟 GitHub 上的版本已經分岔了。
    **不要用這個資料夾的 `.git` 做任何 commit / push，完全忽略它。**
- 真正跟 GitHub 連線、可以 push 的地方：**Replit 的 Shell**（remote 名稱是 `github`，
  已用 fine-grained token 設定好憑證，存在 Replit 的 `~/.git-credentials`）
- 這個專案**有真實使用者在用**，任何一步都要保守，破壞性指令先講後果再做

## 改完之後怎麼交付
1. Claude 直接在本機資料夾 `C:\Users\user\Desktop\話術透視鏡\Script-Insight-Tool` 改檔案
   （這裡的檔案改動會自動同步到 Replit，不需要另外包 tgz 或寫 push.sh）
2. 請使用者到 Replit 網頁版確認檔案內容已經同步過去（眼睛看，不要只信「應該吧」）
3. 請使用者在 **Replit Shell** 跑：
   ```
   git add -A && git commit -m "<這次改動的描述>" && git push github main
   ```
4. 請使用者到 GitHub 網頁重新整理，確認看得到新的 commit 才算成功
5. 如果這次改動有動到資料庫 schema（用 Drizzle），要提醒使用者：
   只改 schema 檔案不夠，開發資料庫也要真的跑過 migration，
   否則 Replit 部署時比對開發庫 vs 正式庫會產生預期外的 SQL（包含 `DROP TABLE`）
6. 請使用者按 Deploy，然後用具體的方式確認改動真的生效
   （例如 `grep -l "新字串" dist/public/assets/*.js`，有輸出才算數，不要用 `| tail` 吞掉錯誤）

## 這個專案的地雷（實際遇過的）
- **Replit 內建的「Connect to GitHub」OAuth 授權會失敗**（跳出「replit.com 拒絕連線」），
  重試也一樣。目前改用 GitHub Fine-grained Personal Access Token 手動接，可行。
  如果之後要重新產生 token：GitHub → Settings → Developer settings →
  Fine-grained tokens，Repository access 選這個 repo，Permissions 的
  **Contents 設成 Read and write**。
- 貼 token 到 Replit Shell 時，**不要**直接嵌在一行指令裡（複製貼上容易被終端機截斷或
  重複貼成好幾份，之前發生過貼了 3 次疊在一起變成 279 字元的情況）。改用：
  ```
  read -srp "貼上 Token 然後按 Enter: " GH_TOKEN; echo "已讀取，長度：${#GH_TOKEN}"
  ```
  貼完先看長度數字合理（fine-grained token 約 93 字元）再繼續，
  接著才用 `printf "https://<帳號>:%s@github.com\n" "$GH_TOKEN" > ~/.git-credentials`
  寫入憑證檔。
- 原本 `.gitignore` 完全沒有 `.env` 相關規則，已經補上：
  ```
  .env
  .env.*
  !.env.example
  *.log
  ```
- 專案根目錄有一個 0 bytes 的空檔案 `backup`（無害，但看到不用緊張，不是備份檔本體）。
- 本機同步資料夾（Script-Insight-Tool）跟 Replit 雲端的 git 歷史是分岔的
  （本機在 `4312dd3`，Replit/GitHub 在 `d3e6f10` 之後），這是預期中的狀況，
  因為兩邊本來就是不同機制在管理 —— 不需要修復，只要記得不要用本機的 `.git`。

## 安全界線
- 不收 token / 連線字串 / API key —— 使用者只在 Replit Shell 自己貼，絕對不貼進對話
- 破壞性指令（`git reset --hard`、`rm -rf` 等）要先講後果，確認使用者理解才執行
- 推送前留意 `git status` / `git diff`，如果看到可疑的敏感檔案，先停下來確認內容
